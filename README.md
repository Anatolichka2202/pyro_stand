# Пиростенд

Текущее приложение `pyro_stand` наблюдает за циклограммой БЦВМ через Debug-модуль КАСУ ПП и напрямую принимает измерения платы пиротестера. Пиростенд **не передаёт циклограмму в БЦВМ**. Описание прежней версии с локальным `cyclogram.ini`, TFTP и однобайтовым COM-потоком сохранено в [архивной инструкции](docs/LEGACY_README.md); эти пути не собираются в рабочий исполняемый файл.

## Источники данных

1. Debug КАСУ ПП: локальный сокет JSONL `kasu.pp.debug.stand.v1`. Приложение проверяет `content_base64`, `byte_count` и SHA-256; различает подготовку файла, подтверждение загрузки, снятие блокировки и актуальность состояния БЦВМ.
2. Плата пиротестера: UDP-кадры от IP платы на порт стендового ПК 5000 либо RS-485 на 115200 бод. Формат кадра: `AA 55`, 96 записей по 10 байт и CRC8; суммарно 963 байта.
3. Карта входов: отдельный утверждённый JSON-файл с входом КП и соответствием действий циклограммы входам ЯПС. Без неё пиростенд показывает план и измерения, но не приписывает измерение действию.

`BCVM_EXECUTION_ENABLED` означает подтверждённое разрешение исполнения, а не физический T0. Плановое T0 берётся из `START_UTC_DATE`/`START_UTC_TIME` полученной циклограммы. Относительное время измерений считается от отметки КП в шкале счётчика платы. Связь часов БЦВМ с UTC и аппаратная точность сканирования этим приложением не доказываются.

## Запуск

Собрать Qt 6 приложение с компонентами Core, Widgets, Network и SerialPort:

```text
cmake -S . -B build/stand -G Ninja -DCMAKE_PREFIX_PATH=<каталог Qt для выбранного компилятора>
cmake --build build/stand --target pyro_stand
```

Для переноса Windows-сборки без установленного Qt запустите `windeployqt --release --no-translations build/stand/pyro_stand.exe` из соответствующего Qt-комплекта и переносите всё содержимое `build/stand`. `build.bat` выполняет этот шаг, если `windeployqt` есть в `PATH`.

На стендовом ПК КАСУ ПП нужна Debug-сборка с включённым модулем и параметром `--debug-stand-socket kasupp-debug-events-v1`. Пиростенд использует то же имя по умолчанию:

```text
pyro_stand --debug-socket kasupp-debug-events-v1 --board-ip 192.168.17.144 --bind-ip 0.0.0.0 --board-port 5000 --mapping <утверждённая-карта.json>
```

Для резервного приёма по RS-485 укажите `--board-serial COM7` вместо UDP. Команда сброса и в этом режиме отправляется по Ethernet: текущая прошивка не принимает её через RS-485. Для сетевого режима адрес компьютера должен соответствовать адресу назначения прошивки платы (`192.168.17.20` в изученной версии), либо прошивку нужно настроить под фактическую сеть. Один приёмник должен владеть UDP-портом 5000: при штатном прогоне Python-приложение пиротестера на том же порту не запускают.

После появления новой циклограммы нажмите «Сбросить результаты платы». Пиростенд ждёт пустой кадр после команды; отдельного ACK команда не имеет, поэтому факт её исполнения по одному пустому кадру доказать нельзя. Если вход уже находится в активном состоянии, пустой кадр может не появиться; перед прогоном это нужно устранить на стенде. Без пустого кадра после команды приложение не рассчитывает привязанные к текущему прогону интервалы.

## Формат карты каналов

Ниже **пример структуры**, а не схема подключения стенда. Значения ЯПС и канала должны быть заменены по утверждённой электрической карте:

```json
{
  "version": "идентификатор-утверждённой-карты",
  "kp": { "yps": 1, "channel": 1, "edge": "rise" },
  "actions": [
    {
      "key": "IGNITE_PYRO_CANDLES_ENGINES_1_TO_8",
      "inputs": [{ "yps": 1, "channel": 2, "edge": "rise" }],
      "tolerance_ms": 2
    }
  ]
}
```

`tolerance_ms` необязателен. Без допуска отображается измеренное отклонение без оценки «в допуске». Одно действие может иметь несколько входов. Повтор одного и того же действия не оценивается: текущая прошивка платы хранит только первый фронт входа, а не историю импульсов.
Если утверждённая схема связывает действие `LIFT_OFF_CONTACT` с тем же физическим входом КП, этот вход можно явно указать и в `actions`; пиростенд сам такого соответствия не создаёт. Один и тот же фронт/спад нельзя назначить двум разным действиям.

## Отчёт и проверки

Кнопка «Сохранить отчёт» создаёт JSON с полученной циклограммой, состояниями Debug, картой каналов и расчётными результатами, а рядом — `.frames.jsonl` с исходными принятыми кадрами платы. Сохраняйте оба файла вместе.

Автоматические проверки:

```text
cmake --build build/stand
ctest --test-dir build/stand --output-on-failure
```

Тест интеграции поднимает локальный сервер Debug и отправляет синтетические UDP-кадры платы. Работа с БЦВМ, реальной платой и проводкой проверяется отдельно на стендовом ПК.
