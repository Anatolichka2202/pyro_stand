# Применение исходного UI-дизайна к IntegrationSession

**Источники:** восстановленная без изменений спецификация `design/spec.md` от 2026-06-21, архивные макеты Ланы `project/design/mockups/FullScreen-v1.dc.html`, `Scenario-v1.dc.html`, `T20-LogPanel-v1.dc.html` (доступны в Git на коммите до `856f400`).

## Обязательные визуальные инварианты

- 1280×800 — целевая исходная геометрия; тёмная палитра и размеры шрифтов из `spec.md`.
- Одна операторская таблица из 7 столбцов: номер, описание, назначенные входы, план, факт, отклонение, статус.
- В таблице одна строка на назначенное событие; неназначенные события и все 96 необработанных входов платы не отображаются.
- Синяя подсветка `#58a6ff` выделяет первое ожидаемое событие, `#1c2d3a` — фон его строки.
- Журнал сессии: `▌ HH:mm:ss УРОВЕНЬ сообщение`, цвет метки по типу события.
- 72px timeline отражает только назначенные события; playhead не может симулировать аппаратное время по системным часам.
- Статусы связи отделены от оценки выполнения, отсутствие связи — нейтральное (серое) состояние, ошибка — красное.

## Различия новой аппаратуры и первоначальной спецификации

1. **Загрузка и пуск:** циклограмму загружает КАСУ ПП; Pyro Stand не предлагает загрузку на борт, установку времени старта или запуск. Сброс платы пиротестера — отдельная подтверждаемая аппаратная операция.
2. **Каналы:** вместо старых фиксированных 8 каналов COM отображаются только входы ЯПС из утверждённой карты соответствия; число назначений может отличаться.
3. **Нулевое время:** физический ноль — КП в счётчике платы. Время до планового T0 на экране считается по UTC часам ПК и явно так подписано; его нельзя интерпретировать как измерение.
4. **Порог:** историческая `spec.md` указывает 5/50 мс, но новый измерительный контракт по умолчанию использует допуск **±1 мс** (или допуск из карты). Цвет итогового факта определяется индивидуальным допуском каждого назначенного входа, не старой шкалой 5/50 мс.
5. **Абсолютные тики:** старый COM передавал один тик за миллисекунду; новая плата работает в микросекундах. Старое название «ФАКТ (ТИК)» не переносится без преобразования аппаратного контракта. До подтверждённого КП значение «ФАКТ МС» недоступно.
6. **Подписи событий:** текущий debug contract предоставляет технический ключ, но не исходный комментарий. Для четырёх событий из утверждённого дизайна применяются проверенные русские подписи; для неизвестных — неизменённый ключ. Полные названия остальных событий должны прийти из утверждённого источника.

Этот файл фиксирует только допустимые отклонения от исходного дизайна, а не заменяет `spec.md` новой эстетикой.
