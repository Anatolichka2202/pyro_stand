# Профиль подключения сигналов

Необязательный JSON выбирается в диалоге «Подключение» отдельно для основного
источника и дополнительного старого COM; CLI: `--wiring-profile <json>` и
`--compare-wiring-profile <json>`. Выбор сохраняется в пользовательских настройках.
Пустой путь означает встроенную историческую проводку. Если явно выбранный файл
недоступен или некорректен, назначения остаются пустыми. Смена профиля закрывает сбор.

Минимальный профиль без утверждённых назначений:

```json
{
  "schema": "pyro.signal-wiring.v2",
  "version": "unassigned-1",
  "catalog_version": "bcvm-c8e14dc-1",
  "kp": null,
  "bindings": []
}
```

`bindings` — массив объектов с `signal_id`, `yps` (1..12), `channel` (1..8),
`edge` (`rise` или `fall`). В интерфейсе индекс групп новой платы — 0..11;
поле JSON yps — слот 1..12. В старом потоке доступны только слоты 1 и, при двух
COM, 2; за пределами источника оценка блокируется. Каждая сессия владеет собственным
измерителем; yps другого независимого измерителя здесь не задаётся.

Доступные `signal_id` определены `expectedSignals()` в command_catalog.h:
peer `bkhoa` либо `bkpob`, поле `yps_bkd.0`, нулевой индекс бита. Привязка сигнала
не выводится из номера пункта ПЗ. Для оценки команды нужны все её ожидаемые
сигналы; они могут находиться в разных группах и иметь разные выбранные фронты.
Неподключённый сигнал пропускается в bindings; команда требует настройки.

`kp` задаёт тот же yps/channel/edge, что binding сигнала
`bkhoa.yps_bkd.0.bit.7`. При подключённом КП этот binding обязателен. Один
физический input+edge не может быть одновременно КП и другим сигналом.
В плане требуется единственное вхождение LIFT_OFF_CONTACT. Другой `kp_action_key`
не поддерживается: подтверждённых альтернатив в текущем каталоге нет.

Старая карта `version/kp/actions` читается для совместимости. Её action.inputs
становятся пригодными для оценки только при полном наборе точных signal_id,
соответствующем определению команды. Позиционный список без signal_id и
информационная команда не получают оценку. Неизвестные схемы/версии каталога
отклоняются. Значение tolerance_ms в старой карте может переопределить ±1 мс;
для v2 действует текущий профиль ±1 мс.

Выбор профиля — запись назначения оператором, а не доказательство прозвонки или
метрологической приёмки. Храните утверждённую схему и акт подключения вместе с
версией профиля. Отчёт сохраняет применённый снимок, исходный JSON, его версию,
SHA-256 снимка, версию каталога и аппаратные ограничения. Одно сохранённое
наблюдение нельзя использовать для нескольких вхождений/повторных импульсов.

Программная проверка формата/коллизий: `tests/tst_integration.cpp`, случаи
`signalWiringAcrossGroups`, `profileChangeInvalidatesEvidence` и
`missingReferencesAndRepeatedActions`.
